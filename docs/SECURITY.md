# DUSTBUNNY SECURITY POLICY
## Bug reporting.
	
Bug reports should include the following:
	- A description of the bug and it effects.
	- Steps to reproduce the bug.
	- What version of Dustbunny the bug affects.
	- What could possibly be causing the bug. (optional)

Upon receiving a bug report, I will review the bug and attempt to recreate the behaviour, and patch it.

If a bug has been discovered that should be reported privately, the current accepted method of doing so is by contacting myself via DM on Discord at @dot_underscore.1703 (or if the username changes, my user ID is 1355702736800448723).

Bugs that should be reported privately include, but do are not limited to:
	- Bugs the jeopardise the security of the user, the users machine, or the shell.
	- Unintended command execution.

Otherwise, bugs that can be reported publicly may be reported via:
	- Again, a DM to myself on Discord
	- Github Issues

## Support Policy
Dustbunny will receive support for the most recent MAJOR release (compliant to Semantic Versioning), and the previous MAJOR release.
For example, on version 5.x.x, both 5.x.x and 4.x.x will be supported.
Support for versions that are not the most recent fill not include feature additions, and strictly bug fixes. Feature additions will be added to the recent MAJOR release.
Any version older than the previous version is considered to be in END-OF-LIFE (EOL), and it is strongly recommended that you upgrade to a supported version.
EOL versions will not receive bug fixes or features.
